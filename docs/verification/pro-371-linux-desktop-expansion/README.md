# T3 Code e VoiceStudio su Ubuntu 24.04 amd64

Il 27 novembre 2026 entrambe le app hanno completato installazione, apertura grafica, aggiornamento, seconda apertura e rimozione con il NativeBackend di Sh*ftAnything in un guest QEMU isolato su AX42.

- **T3 Code 0.1.12 → 0.1.13.** La schermata iniziale offre l'opzione di avviare l'app senza agenti. Il ciclo ha lasciato scollegati account e agenti di terze parti. [Release precedente](https://github.com/pingdotgg/t3code/releases/tag/v0.1.12), [release aggiornata](https://github.com/pingdotgg/t3code/releases/tag/v0.1.13), [licenza MIT](https://github.com/pingdotgg/t3code/blob/v0.1.13/LICENSE), [apertura precedente](t3code/open-old.png), [apertura aggiornata](t3code/open-new.png), [log](t3code/native-lifecycle.txt).
- **VoiceStudio 0.5.7 → 0.5.8.** L'AppImage ufficiale corrisponde all'edizione locale e gratuita. Il produttore distribuisce Pro e Cloud separatamente. Il flusso del launcher arriva alla configurazione iniziale, dove VoiceStudio richiede un download aggiuntivo per installare il motore locale e poi i modelli vocali. La prova si ferma prima di questi download. [Release precedente](https://github.com/debpalash/VoiceStudio/releases/tag/v0.5.7), [release aggiornata](https://github.com/debpalash/VoiceStudio/releases/tag/v0.5.8), [edizioni e licenza AGPL-3.0](https://github.com/debpalash/VoiceStudio/blob/v0.5.8/README.md#pro-and-cloud), [apertura precedente](voice-studio/open-old.png), [apertura aggiornata](voice-studio/open-new.png), [log](voice-studio/native-lifecycle.txt).

L'installazione iniziale ha usato la risposta ufficiale GitHub del tag precedente. L'aggiornamento ha interrogato l'API GitHub per la release più recente. Per ogni versione sono stati verificati dimensione, SHA-256 e versione rilevata dopo l'installazione. Il launcher ha creato la voce desktop e l'icona, poi le ha rimosse insieme all'AppImage preservando un file utente di prova. Le quattro aperture hanno usato una rete limitata a loopback e un portachiavi temporaneo. Per T3 Code il controllo della seconda apertura è ripartito dallo stato aggiornato dopo aver esplicitato il nome della voce desktop nel test: il file manager generava una seconda voce per il protocollo dell'app.

Le due ricette valgono per Linux x64 con FUSE 2. Versioni successive possono comparire in GitHub, ma prima che il launcher permetta di installarle o aggiornarle serve una ricevuta per il loro pacchetto ufficiale con tag, dimensione e SHA-256 verificati. [Requisiti AppImage](https://docs.appimage.org/user-guide/troubleshooting/fuse.html).

Recordly resta fuori dalle ricette Linux di questo lotto. La versione 1.3.3 si installa ma il lancio standard abortisce: Electron rifiuta il permesso del suo helper SUID in questo ambiente. Il file desktop ufficiale specifica `--no-sandbox`. [Release verificata](https://github.com/webadderallorg/Recordly/releases/tag/v1.3.3).

Il primo lotto ha escluso Paseo dopo un errore di avvio del server locale nel guest. Il collaudo successivo ha riprodotto la causa, arrestato in ordine il server del profilo temporaneo e completato il ciclo. [Prova Paseo](../pro-371-paseo-linux/README.md).

[Sonda Rust](verify_native_appimages.rs). Per ripetere la prova, compilarla come binario della crate native e usare un profilo Linux isolato con `Applications`, directory XDG locali e il file `.shift-native-appimage-proof`. La sonda accetta l'ID dell'app e una fase fra `install`, `open-old`, `update`, `open-new` e `remove`. Le fasi di apertura richiedono una sessione grafica. Per ripetere il passaggio `update`, GitHub deve ancora riportare come ultima la release indicata nella sonda.
