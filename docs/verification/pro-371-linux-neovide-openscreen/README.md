# Neovide and OpenScreen on Linux x64

On 2026-11-28 an isolated Ubuntu 24.04 x86_64 guest completed the native install, launch, update, launch and uninstall sequence for both publisher AppImages. The prior tag came from GitHub's release API. The update was discovered through `GitHubSource` against the live stable release. Each installed file matched the publisher SHA-256 and size, and the launcher's desktop entry and icon were verified. Uninstall removed the managed binary, entry, icon and manifest record, and kept the synthetic profile data. The old OpenScreen binary was also absent after update.

- **Neovide 0.17.3 → 0.17.4.** Both X11 editor windows opened with Neovim 0.12.6 from its official x86_64 archive on `PATH`. On the minimal X11 guest the initial launch diagnosed missing `libxkbcommon-x11`. Installing Ubuntu's `libxkbcommon-x11-0` resolved it. The app entry lists the prerequisite. The bundled menu icon is from the publisher's Flathub entry. [Installation documentation](https://neovide.dev/installation.html), [0.17.3](https://github.com/neovide/neovide/releases/tag/0.17.3), [0.17.4](https://github.com/neovide/neovide/releases/tag/0.17.4), [Neovim 0.12.6](https://github.com/neovim/neovim/releases/tag/v0.12.6), [icon](https://flathub.org/apps/dev.neovide.neovide), [lifecycle](neovide/lifecycle.txt)
- **OpenScreen 2.3.0 → 2.4.0.** Both capture toolbars opened using the publisher's Electron sandbox defaults. The screen source was the guest's virtual display. The test did not record or export video. The menu icon comes from the publisher repository. [2.3.0](https://github.com/getopenscreen/openscreen/releases/tag/v2.3.0), [2.4.0](https://github.com/getopenscreen/openscreen/releases/tag/v2.4.0), [icon](https://github.com/getopenscreen/openscreen/blob/main/design/assets/logo-icon.png), [lifecycle](openscreen/lifecycle.txt)

Each launch ran as an unprivileged guest user with an isolated Xvfb display and loopback-only network. Both versions' original PNGs were reviewed. The Linux recipe accepts the exact AppImage receipts here. A future tag without a reviewed receipt remains outside native installation. Existing macOS Apple Silicon DMG and signing rules are covered by the core suite.

To reproduce, copy `verify.rs` to `crates/native/src/bin/native-appimages-next237.rs` in a scratch checkout and build it with `cargo build --locked -p artcraft-launcher-native --bin native-appimages-next237`. In an isolated Ubuntu 24.04 amd64 guest named `shift-launcher-qa`, install `libfuse2t64`, `libxkbcommon-x11-0`, a software OpenGL stack, `xvfb`, `xauth`, `x11-apps`, `x11-utils`, `xdotool`, `xfwm4`, `dbus-x11` and `gnome-keyring`. Verify the Neovim 0.12.6 archive against its release digest and extract it to `/home/qa/qa-neovim`. Copy the probe and `run.sh` into `/home/qa`, with the script named `native-appimages-guest-next237.sh`. As the disposable `qa` user create `catalog-evidence`, then run the script once with `neovide` and once with `openscreen`, in fresh profile directories.
